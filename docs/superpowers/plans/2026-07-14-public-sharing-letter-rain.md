# Public Sharing and Letter Rain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist greetings and media in Supabase, deploy the app behind a canonical HTTPS URL, and animate the signature as falling letters that settle into a centered sentence.

**Architecture:** Next.js route handlers use a server-only Supabase secret client for database writes, reads, and signed upload creation. The browser uploads images directly to a public Supabase Storage bucket with short-lived signed tokens, while greeting pages retrieve durable authored JSON through the app API. Framer Motion performs transform-only letter rain with semantic fallback text and reduced-motion support.

**Tech Stack:** Next.js 16.2.10, React 19.2.4, TypeScript, Supabase JS 2.110.3, PostgreSQL/RLS, Supabase Storage, Framer Motion 12.42.2, Vitest, Vercel CLI.

## Global Constraints

- Public links must use `NEXT_PUBLIC_SITE_URL` and remain valid after process restarts.
- Use `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in browser code and `SUPABASE_SECRET_KEY` only in server-only modules.
- Enable RLS on every table in the exposed `public` schema; browser roles receive no direct greeting-table privileges.
- Uploaded media is public-by-link, uses random object paths, accepts only JPEG/PNG/WebP/GIF, is limited to 10 MiB per file and 20 files per greeting.
- Generation succeeds only after durable persistence succeeds when Supabase is configured.
- Letter animation uses only opacity and transform, runs once on scroll entry, and renders immediately for reduced-motion users.
- Do not commit credentials, access tokens, project references containing secrets, or `.env` files.
